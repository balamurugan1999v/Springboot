Springboot

What is springboot:
	Springboot is java based spring framework used in Java web application
	It is used to build microservice based application
	It is used rapidly build the application with less no of configurations
	It is having build in servers like tomcat and jetty.
	
What is the advantage of Springboot over Spring:
	Auto configuration - Spring boot automatically configures the jar dependencies which is in the classpath of the project.
	@EnableAutoConfiguration - is the annotation used of this
	It is automatically configure the default error page, dispatcher servlet, datasource and configure webjars
	
Annotations:
	@SpringBootApplication - This annotation used in the main class of the application.
		It encapsulates @Configuration, @EnableAutoConfiguration and @ComponentScan annotations.
	
		Example:
		@SpringBootApplication
		public class DemoApplication{
			public static void main(String args[]){
				SpringApplication.run(DemoApplication.class, args);
			}
		}
		
	@SpringBootConfiguration - 
		It is the automated version of @Configuration annotation in Spring.
		In Most of the SpringBoot application using this feature via @SpringBootApplication annoatation.
		If we want to create a custom bean then class we need to mention as @Configuration.
	@ComponentScan - Which will scan all the @annotations in the subdirectories.
		
	@RestController - It is used to create Controller class, which contains both @Controller and @ResponseBody
	
	@Column - It is used to specify the column name we used in the tables.
		@Column(name = "Student_name") 
	@Table - This we use at class level and mention the entity class with the table name.
		@Table(name = "Student") 
	@Transient - It is used to skip the persistance in the entity class.
	@OneToMany - This is contains one user can have multiple rows in the another table
	@ManyToOne - This is Inverse of above one. This table rows are reference for another table one row.
	@OneToOne - This is exactly primary and foreign Key with one row.
	@ManyToMany - This is multipleRows can be referenced in multipleRows of another table
	@OneToMany - One student have multiple laptops.
	@ManyToOne - Multiple laptops belongs to one student.
	@OneToOne - One Laptop should be assigned only one student and vice versa.
	@ManayToMany - In Computer lab any of the Laptop can be assigned to any of the Student
	@Component - It is general purpose annotation like utility, helpers class. It will also work as @Service, @Controller, @Repository
	
	@Qualifier:
		@Qualifier("beanName")
		It is used to inject a specific bean when multipleBeans with same type.
		For example we have two classes which is implementing one single interface
			interface Pizza{
				String getData()
			}
			class Veg implements Pizza{
				public String getData(){
					return "Veg";
				}
			}
			class NonVeg implements Pizza{
				public String getData(){
					return "Non Veg";
				}
			}
		
		Here if we are autowiring Pizza interface then spring ioc will get confused which implementation need to be used whether veg or nonveg. In order to avoid that if we want to use Veg then we can use @Qualifier("veg") then it will call the respective class.

SpringSecurity:
	By enabling spring-security dependancy in pom springboot automatically apply the security for the application. The user name will be user and password we can see in the console while application coming up.
	If we want to use our custom creds then need to mention them in the application.properties
		spring.security.user.name = user
		spring.security.user.password = pass
	This will work for all the getRequest and not work for Post,PUT and Delete, it will give 401 error.
	For all the DB write action need to send csrf-token in post request headers.
	In order to avoid the above issue, we need to manually setup our own Security. Steps are below
		1. Create a config class
		2. Use @Configuration and @EnableWebSecurity annotations to use for security.
		3. create a method with @Bean annotation and the return type will SecurityFilterChain and params is HttpSecurity
			@Bean
			public SecurityFilterChain securityFilterChain(HttpSecurity http){
				return http.build(); --> It will return SecurityFilterChain
			}
		4. In My case csrf need to be disabled, for all the http calls authendication need to be happened, it need to be accessible via postname, singleSessionId can be mained until logout.
			http
				.csrf(customizer -> customizer.disable()) //-- It is used to disable the csrf
				.authorizeHttpRequests(request -> request.anyRequest().authenticated()) // -- It is used to authendicate each http request.
				.httpBasic(Customizer.withDefaults()) // It is used to access from Postman
				build();
			
		
ConfiguringMultipleDatabase:
	1. Create datasouce details in app.properties
	2. Create domain classes for each DB
	3. Create Repository classes/Interface for each DB
	4. Create a config class to configure -> Datasource, EntityManager, TransactionManager
		1. Use @Configuration at class level
		2. Create a @Bean with primaryDB name
		3. Use @Primary for collecting the datasource by passing @ConfigurationProperties(prefix = "")
		4. Return DatasourceBuilder.create().build(); --> It will return datasource obj
		5. Create a next Bean for EntityManager, passing parameter as EntityManagerFactoryBuilder and return type as LocalContainerEntityManagerFactoryBean
		6. put the datasource which we got it from line 4, add properties if we have any dialect, ddl-auto, show-sql, add the entity Package and build.
		7 Create a next Bean for transactionManager by passing @Qualifier with EntityManagerBeanName LocalContainerEntityManagerFactoryBean and return type as PlatformTransactionManager
			return  new JpaTransactionManager(localContainerEntityManagerFactoryBean.getObject())
	5. Add the @EnableTransactionManagement and @EnableJpaRepositories(entityManagerFactoryRef = BeanName, basePackage ="repoPackage", transactionManagerRef = BeanName)
	
CustomExceptionHandling:
	Create a class and extends RunTimeException class
	Create a constructor with one parameter which is error message. Inside the constructor call the super class with the error message like super(errorMessage);
	Create a customExceptionHandler class and create a method with respective errorMessage name and annotate with @ExceptionHandler
	
	public class ExceptionHandler{
	
		@ExceptionHandler(ExceptionClassName.class)
		public ResponseEntity<String> methodName(ExceptionClass obj){
			return ResponseEntity<String>(obj.getMessage(), HttpStatus.NOT_FOUND);
	}

HTTP Methods:
	GET: It is used to collect the data.
	POST: It is used to create a data newly
	PUT: It is used to update the existing data
		It is used for retry / autoretry, because if it calls multiple time nothing will happened newly
	DELETE: It is used to delete the data.
	PATCH: It is used to partially update the data. for example if we have DTO like 
	{
		name:
		age:
		address:
	}
	
	If you want to update any particular one then you can like below
	{                       {					{
		name: 					age:				address:
	}						}					}
	
	Which will update this particular spec where as put will replace whole data into single data, which means it will delete the other 2, whatever passed in the request it will replace that with existing records.
	
	Idempotent: GET, PUT, DELETE, PATCH are idempotent because, if we retried the same api with same request payload it should not duplicate anything same result would be happened.
